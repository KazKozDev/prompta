# catalog.json — машиночитаемый каталог техник

Фундамент пайплайна «поток мыслей → промпт». Собран из
[`../archive-org-prompting/techniques-map.md`](../archive-org-prompting/techniques-map.md), то есть
каждая запись прослеживается до страницы первоисточника.

```bash
python3 catalog/validate.py        # проверка структуры и полноты
```

## Что внутри

| | Кол-во |
|---|---|
| Всего записей | 89 (версия каталога 0.2.0) |
| `status: "ready"` — есть шаблон синтеза, «когда не подходит», конфиг | 64 |
| `status: "procedure"` — не промпт, а процедура: шаги выполнения вместо шаблона | 18 |
| `status: "index-only"` — настройки и риски, промптом быть не могут | 7 |
| Категорий таксономии | 16 |

Разделение намеренное и исчерпывающее — «заглушек» не осталось:

- **64 `ready`** — есть шаблон, «когда не подходит» и конфиг; синтез возможен.
- **18 `procedure`** — это не промпт, а процедура над данными или моделью (KNN-отбор, RL-оптимизаторы,
  ансамбли). Вместо шаблона у них `procedure`: список шагов, который можно выполнить или показать.
- **7 `index-only`** — 3 настройки генерации (temperature, top-k/top-p, длина вывода) и 4 риска
  безопасности (инъекция, джейлбрейк, утечка промпта, выдуманные пакеты). Промптом быть не могут
  по природе, и притворяться шаблоном не должны.

**Выбор** видит весь каталог, **синтез** — только `ready`, **процедуры** показываются шагами.

## Схема записи

| Поле | Тип | Назначение |
|---|---|---|
| `key` | string | Стабильный идентификатор, латиница. Используется в API и логах |
| `name` | string | Человеческое название из карты |
| `kind` | enum | `technique` \| `setting` \| `prompt_type` \| `risk` |
| `category` | enum | Раздел таксономии (16 значений) |
| `task_types` | string[] | Типы задач, где техника уместна. Пусто — ограничений нет |
| `task_types_source` | enum | `explicit` (задано вручную) \| `category-default` (выведено из категории) |
| `execution` | enum | `single_call` \| `multi_step` \| `n_calls_vote` \| `tool_loop` \| `optimizer_loop` \| `postprocess` \| `none` |
| `when_to_use` | string | Из карты. Опора для выбора техники |
| `when_not` | string \| null | Когда техника вредит. Заполнено у `ready` |
| `cost_calls` | int \| string | Оценка числа вызовов LLM (`1`, `"5–10"`, `0`) |
| `config` | object | `temperature`, `top_p`, `max_tokens_hint`, `rationale` |
| `template` | string \| null | Остов промпта с плейсхолдерами `{{...}}`. Только у `ready` |
| `example` | string | Пример из первоисточника |
| `source_ref` | string | `whitepaper, с. 29–32` или `§2.2.3, с. 13` |
| `source_docs` | string[] | ID документов из `../archive-org-prompting/md/` |
| `related` | string[] | Соседние техники: для «покажи альтернативу» |
| `status` | enum | `ready` \| `index-only` |

## Политика конфига

`temperature` в каталоге — это **стартовая рекомендация, а не истина**: значение выведено из типа
техники и подкреплено `rationale`.

| Категория | temp | Почему |
|---|---|---|
| `answer_engineering` | 0.0 | Извлечение должно быть детерминированным |
| `agents`, `rag` | 0.1 | Действия и цитаты не должны быть «творческими» |
| `context`, `reasoning`, `decomposition`, `self_critique`, `icl` | 0.2 | Стабильность важнее разнообразия |
| `zero_shot_boost`, `automation` | 0.3 | Меняется формулировка, не содержание |
| `pedagogy` | 0.5 | Вопросы должны быть разнообразными |
| `ensembling`, `optimization` | 0.7 | Ансамбль и поиск живут только на разнообразии |
| `generation_config`, `security` | `null` | Температура — сам предмет настройки либо не применима |

## Как это использует пайплайн

1. **Выбор.** Модель получает бриф + компактную проекцию каталога (`key`, `name`, `category`,
   `when_to_use`, `when_not`, `cost_calls`) и возвращает `key` + причину + уверенность.
   Обязательное правило: самая дешёвая техника, которая закрывает бриф.
2. **Синтез.** Берётся `template` выбранной техники, плейсхолдеры заполняются из брифа; `example`
   идёт как few-shot-подсказка о качестве; `config` переносится в рекомендации пользователю.
3. **Проверка.** `when_not` + рубрика дают материал для критика: если бриф попадает в `when_not`,
   выбор отклоняется до генерации.

## Известные пробелы (следующие шаги по данным)

- `task_types` заполнены: 25 записей вручную, 64 выведены из категории, 8 (настройки и риски) — без
  типов. Выведенные не проверены на реальных задачах: eval должен показать, где категория врёт.
- 7 записей `index-only` — это 3 настройки генерации и 4 риска безопасности (по природе не промпты) — их нельзя синтезировать, только рекомендовать.
- Нет `language`/`modality` — при добавлении мультимодальности схема расширяется
  (`modality: ["text", "image"]`), и записи без нужной модальности отсекаются на выборе.
- Нет рубрики оценки — она появится вместе с eval-набором, отдельным файлом.

## Как пересобрать

Каталог генерируется скриптом из карты, а не правится руками:

```bash
python3 catalog/build_catalog.py   # пересобрать catalog.json из techniques-map.md
python3 catalog/validate.py        # проверить структуру
npm test                           # инварианты пайплайна
```

`when_to_use`, `example`, `source_ref` берутся из `techniques-map.md`; `template`, `procedure`,
`when_not`, `related`, `execution` заданы в `build_catalog.py`. При правке карты каталог нужно
перегенерировать, иначе они разъедутся.
